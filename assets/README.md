# Application icon

`GlidePod.icon` is the primary, editable Icon Composer document. Open it in the Icon Composer supplied with Xcode 27. It keeps the selected B glass design: two square package faces, their fine contours and the foreground opening in five SVG layers. A third group supplies the emerald radial background, bright at the center and darker around the perimeter. See the [reconstruction record](../.agents/design/icon-composer/README.md) for geometry, previews and validation.

The source contains precise vector geometry and explicit alpha gradients for clean glass overlap. Apple's renderer supplies the system mask, specular treatment and restrained shadows. Strong refraction is disabled to avoid distorting the overlap. Keep the emerald, mint and ivory palette, foreground opening, equal square proportions and centered composition when refining the geometry. Dark appearance has explicit color and alpha overrides. No AI-generated texture, baked background mask, letters or Apple artwork is included.

The background is a continuous 1024-pixel radial fill generated by `tools/generate-icon-background.swift` from `icon-background.json`. It matches Icon Composer's 1024-unit canvas and the largest 512-point @2x app-icon rendition; a larger untransformed bitmap is center-cropped by Icon Composer. Color stops, center and radius are editable parameters; `tools/export-icons.py` rebuilds the background and both document copies before exporting. The softly lit center sits beneath the glass overlap, with a broad, restrained falloff to the darker emerald perimeter. The current palette reduces the earlier radial glow and uses softer jade/ivory face highlights, keeping the opening and narrow contours distinct at small sizes. This analytic raster is used only for the smooth color field; the package artwork remains vector.

`tools/package-dev.py` compiles the document with `actool`, then includes `Assets.car` and both `CFBundleIconName`/`CFBundleIconFile` keys. Because actool emits only a partial ICNS, `macos/packaging/ExportAppIcon.swift` renders a complete fallback from the compiled catalog: 16, 32, 128, 256 and 512 points at both 1x and 2x, through 1024 physical pixels. This preserves the system inset and material rendering without enlarging a small image. Keep the layered catalog; do not replace it with a flattened PNG-only icon. The older `glidepod-icon.svg` is retained only as historical flat artwork; active UI and documentation use the current layered design.

Run `rtk proxy python3 tools/export-icons.py` to render the six macOS appearances and 16/32/64/128-pixel previews with design generation 27. Review PNGs remain under `evidence/ui-refinement/`. The same command generates 256-pixel documentation previews and 40-point sidebar exports at 1x/2x/3x (40/80/120 pixels), for both appearances, in `assets/brand/` and `.agents/prototype/assets/`. GPUI selects the sidebar rendition from the window's current backing scale; the prototype uses `srcset`. Avoid shrinking a large preview through GPUI's bilinear atlas sampler, which has no mipmaps and aliases fine contours. The 256-pixel preview is retained for README and other browser-rendered sizes. Xcode 27 is required; compilation targeting macOS 15 does not establish runtime validation on macOS 15.

References: [Icon Composer](https://developer.apple.com/icon-composer/), [creating an app icon](https://developer.apple.com/documentation/xcode/creating-your-app-icon-using-icon-composer), [Apple app icon guidance](https://developer.apple.com/design/human-interface-guidelines/app-icons).
